Compio

Compio is a library that stores many named files in a single archive with transparent block compression. Data is split into blocks that are compressed independently and indexed by a B-tree, so reads, writes, inserts and erases touch only the blocks they need.

  • Random access to compressed data, including insert and erase in the middle of a file
  • Per-block compression: ZLIB, LZ4, Zstandard, Brotli or a custom codec, applied in parallel
  • Crash safety: write-ahead log, atomic header publication, checksums on every block and index node
  • Transactions that group several writes into one atomic step
  • Space management: different allocation strategies, automatic compaction and defragmentation
  • Thread-safe, with C and C++ APIs; builds on Linux, macOS and Windows

Building

Requires Git, CMake 3.15+ and a C++17 compiler. Dependencies are built by the bundled vcpkg submodule (on Linux and macOS it needs curl, zip, unzip, tar).

git clone --recurse-submodules https://github.com/lovyagin/compio
cd compio
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
ctest --test-dir build --build-config Release

To use your own dependencies pass -DCMAKE_TOOLCHAIN_FILE=... or -DCMAKE_PREFIX_PATH=....

Usage

#include <compio.h>
compio_config config;
compio_build_default_config(&config);
compio_archive *archive = compio_open_archive("data.compio", "w+", &config);
compio_file *file = compio_open_file("notes.txt", archive);
compio_write("hello, compio", 13, file);
char buffer[13];
compio_seek(file, 0, COMPIO_SEEK_SET);
compio_read(buffer, sizeof buffer, file);
compio_close_file(file);
compio_close_archive(archive);

Durability

An archive stays consistent after a process kill or a power loss in every wal_sync_mode. With COMPIO_WAL_SYNC_ALWAYS every committed operation survives both. The default, COMPIO_WAL_SYNC_NORMAL, loses nothing on a process kill, and a power loss may drop the operations since the last compio_flush, batch end or close. COMPIO_WAL_SYNC_OFF may lose those operations on a process kill too. A new archive is safe from creation only in ALWAYS mode; in the others, flush it once after creating it. After a failed fsync an archive refuses further writes with EIO; reopen it to continue from the last durable state.
